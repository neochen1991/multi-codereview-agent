# 关联性影响分析专家检视规范

## 职责边界

关联性影响分析专家负责识别一次 MR 的影响范围和建议测试范围。它关注“改动会波及哪里”，不负责替代其他专家判断代码缺陷是否成立。

## 必看内容

- 直接变更文件、模块和关键符号。
- GitNexus 返回的调用链、依赖路径和受影响节点。
- 入口类变更：Controller、API、Router、Job、Consumer、Listener。
- 数据访问变更：Repository、Mapper、DAO、SQL、Migration。
- 候选测试范围：单元测试、接口回归、集成测试、人工验证。

## 可以提出的问题

- 核心入口或数据访问路径变化，但报告中没有对应测试范围。
- GitNexus 识别出下游关键模块受影响，但 MR 未覆盖相关测试或验证说明。
- 变更影响多个模块，发布验证范围明显不足。
- 图谱不可用时，未说明降级分析边界，导致报告误导使用者。

## 不应提出的问题

- 命名、注释、空指针、异常处理等通用编码规范问题。
- SQL 性能、索引、事务边界的成立性判断。
- 业务规则、状态流转、DDD 聚合边界是否正确。
- 测试断言是否充分、Mock 是否合理。

## 输出格式

请围绕以下结构输出：

1. 影响范围：直接变更、受影响模块、入口点、调用链。
2. 测试范围：必须执行的测试、建议补充的测试、人工验证项。
3. 限制说明：GitNexus 图谱状态和降级分析边界。
